# 律析 LawFlow

律析 LawFlow 是一个本地优先的法律材料工作台。它将复杂 DOCX、TXT 或 Markdown 材料转换为可确认的章节方案、可审阅初稿、关键主张依据和待核验任务。

首版不替代律师作出法律意见。所有生成内容均应经过律师审核后使用。

## 客户端下载与更新

LawFlow 的客户版采用本地桌面 App，不依赖公共业务后端。正式版本通过独立的公共 GitHub Releases 仓库提供签名、公证后的 macOS 安装包；应用启动时只检查该仓库的最新版本，检查失败不会影响本地使用。

源码仓库当前为私有仓库，不能作为普通客户的直接下载页。首次发布前需创建公共二进制仓库并配置签名、公证和 Release Token。完整流程见 [`docs/desktop-release.md`](docs/desktop-release.md)。

## 已实现能力

- 本地项目空间：按专题、客户或案件归档材料和输出物；
- DOCX、TXT、Markdown 解析：保留标题路径、段落顺序和稳定材料块编号；
- 材料地图：目录、主题信号、规范名称与待核验候选项；
- 章节方案：先生成、编辑并确认，后生成正文；
- 三种交付模板：合伙人十分钟速览、客户法律简报、法声 LexCast 解读稿；
- 关键主张级材料回链：区分原文直接支持与综合归纳；
- 待核验任务：与材料块关联，可更新状态、负责人和截止时间；
- 成果包导出：Markdown、任务表、证据映射和审计摘要；
- 本机模型服务配置：可记录 DeepSeek、OpenAI 或兼容 OpenAI 协议的服务配置。审阅底稿使用本地模板；叙事大纲与讲稿已接入外部文本模型。

## 本地启动

使用当前 Python 环境：

```bash
cd /path/to/lawflow
python3 -m uvicorn app.main:app --host 127.0.0.1 --port 8080
```

浏览器打开：

```text
http://127.0.0.1:8080
```

也可以使用 Docker：

```bash
docker compose up --build
```

## 音频与画像优化

- 讲稿页的“新增 / 编辑画像”支持手工新建、另存预设、自定义画像修改，画像持久化到 SQLite。
- 在画像编辑器中粘贴 100–30000 字播客转写文本，提取可编辑的风格草稿，确认后保存。可选配置独立的兼容 `/audio/transcriptions` 服务，上传不超过 20 MB 的音频片段并先核对转写结果。此功能提取表达风格，不做音色克隆。
- 音频页可选文本模型口语润色、编辑完整脚本、TTS 前 180 字试听和完整 MP3 合成。完整合成按句子与段落拆分（每段至多 1200 字符），使用 FFmpeg 合并并读取实际时长。
- 编辑脚本后旧音频失效；修改源讲稿会提示已有脚本需要更新。项目成果包包含叙事讲稿、DOCX、口播脚本、已有 MP3 和材料回链。

### 中文播客试听配置

“本地设置”选择 MiniMax 原生接口。TTS 地址留空使用 `https://api.minimax.cn/v1`，模型留空使用 `speech-2.8-hd`，音色填服务商提供的 `voice_id`，密钥填独立 MiniMax 密钥。切换服务时同步修改地址、模型与音色，不能沿用其他服务的音色标识。建议从 1.0 倍速开始，用同一段含术语、数字与长句的文本试听后再决定。

兼容 `/audio/speech` 的接口仍可用。语气指令只适用于支持 `instructions` 参数的模型；不支持时请留空。MiniMax 不发送这个参数。浏览器语音用于校对，不能代表云端 TTS 的音质。

本地完整音频合成需要 `ffmpeg` 和 `ffprobe`，Docker 镜像已包含。模型和音频服务调用可能收费；未配置密钥时可使用本地脚本整理、编辑和手工画像。

### 已知边界

- 同一项目可归档多份材料，但一次讲稿仍以一份材料为范围；跨文档综合尚未实现。
- 材料地图与核对任务基于规则/关键词，不等同于语义冲突检查或外部权威来源检索。
- 选择范围超出上下文预算时明确拒绝并提示拆分，不再静默截掉材料。篇幅为目标预算，不保证模型严格遵循或精准达到收听时长。
- 长稿生成和音频合成仍为同步请求，失败需重新运行；尚未实现持久化任务队列和断点续跑。
- 画像更新作用于后续生成，已有成稿不会自动改写。口语润色仍需核对事实，试听不代表内容已审阅。
