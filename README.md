# 声息 Shengxi

**把没有时间读完的东西，带到路上。**

声息是一款本地优先的 macOS 内容整理与收听应用。将收藏的文章、报告和笔记导入书架后，你可以保留原文直接朗读，也可以让 AI 帮你提炼要点、规划章节，经过人工确认后生成适合收听的讲稿与音频。

本仓库沿用早期项目名 `lawflow`，面向用户的产品名称为 **声息 Shengxi**。当前仍是早期版本，功能和安装包状态以具体版本说明为准。

## 从一篇文字到可听内容

1. **导入并核对原文**：粘贴公众号或公开网页链接，预览抓取到的标题、完整正文和结尾；也可以上传 PDF、DOCX、TXT、Markdown 文件，或直接粘贴正文。网页读取失败时可改用文件或粘贴文本。
2. **选择收听方式**：
   - **原文朗读**：保留文章写法，不经过 AI 改写，直接制作语音。
   - **先听要点**：把长文章整理为较短的速听内容。
   - **分章节学习**：先选择材料、检查章节与大纲，再生成可审阅的讲稿。
3. **试听、确认并保存**：调整音色和语速，试听后生成 MP3；多章内容可合成为带章节标记的 M4B。有需要时，还能导出 Markdown、DOCX 和相关审阅材料。

书架支持收藏夹归类，章节内容可记录阅读进度。首页提供完整示例，可以先试听，再决定是否导入自己的材料。

## AI 在哪里发挥作用

原文朗读不需要 AI 改写。选择“先听要点”或“分章节学习”时，AI 可根据用户选定的材料协助规划章节、生成大纲和讲稿。用户先确认大纲，再审阅成稿；重要事实、引述和待核验内容仍需人工检查。

当前提供三种协作方式：

| 方式 | 怎么使用 | 材料去向 |
| --- | --- | --- |
| 在声息中连接模型 | 配置 OpenAI、DeepSeek 或兼容接口，在应用内生成大纲和讲稿 | 用户允许后，将所选材料发送给配置的模型服务 |
| 使用本机 Agent | 安装仓库中的 [LawFlow Skill](skills/lawflow/SKILL.md)，让支持 Skill 的 Agent 读取选定项目、生成内容并回写声息 | 由所使用的 Agent 和模型服务决定；声息中无需另配文本模型密钥 |
| 复制给外部 AI 助手 | 复制选定材料包，在外部助手中生成 Markdown，再粘贴回声息审阅 | 用户主动复制的材料会进入对应服务 |

声息还保留面向专业材料的来源范围、章节审阅、待核验提示和导出记录。**待核验提示不等于事实核查已经完成**；生成内容不能直接代替专业判断或正式法律意见。

## 安装与体验

### macOS 内测包

[Releases](https://github.com/hey-elaine/lawflow/releases) 提供已发布的安装包。目前公开的 `v0.1.0-beta.1` 是较早的 Apple Silicon 内测构建，可能不包含 `main` 分支的最新“声息”界面与功能。该包采用临时签名，尚未完成 Apple Developer ID 公证；安装要求和已验证范围请以[该版本说明](https://github.com/hey-elaine/lawflow/releases/tag/v0.1.0-beta.1)为准。

### 从源码运行当前版本

```bash
git clone https://github.com/hey-elaine/lawflow.git
cd lawflow
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 -m uvicorn app.main:app --host 127.0.0.1 --port 8080
```

在浏览器打开 <http://127.0.0.1:8080>。桌面打包方式见[桌面版发布说明](docs/desktop-release.md)。完整音频合成及 M4B 导出需要本机安装 FFmpeg（含 `ffprobe`）；仅导入、整理和审阅文字不需要它。文本模型可以在应用“设置”中连接；使用本机 Agent 协作或原文朗读时，不必为文本改写配置模型。

## 音频与 iPhone 的当前边界

声息目前在 Mac 上生成和导出 MP3、M4B，**还没有手机收听页，也不会同步 Mac 与手机的播放进度**。M4B 带有章节标记，但不能保证通过隔空投送后直接进入 iPhone“图书”。如需在“图书”中收听，可先将 M4B 导入 Mac“图书”，再通过访达同步到 iPhone；同步前请留意访达对现有内容的提示。只想快速带走音频，可以把 MP3 放进 iPhone“文件”中播放。

## 未来规划：发送到手机

我们计划先用手机网页打通收听流程，而不是把 M4B 导入“图书”作为产品的唯一移动端路径。以下能力**尚未实现**，也没有确定发布日期。

1. **保留章节音频**：生成后保存可复用的逐章音频和章节信息，避免手机端重新合成或从 M4B 拆分。
2. **扫码领取**：Mac 音频页提供“发送到手机”；用户主动选择后，将这本书加密并临时上传，生成一次性领取二维码。领取链接可过期、可由 Mac 端撤销；桌面项目和完整本地服务不会因此开放到局域网。
3. **手机收听页**：扫码后在浏览器查看封面、章节与播放进度，支持按章播放、倍速、继续收听和下载章节。首版以手机本地续听为目标，不承诺跨设备进度同步。
4. **真机验收后扩展**：在 iPhone 上验证锁屏、后台播放、耳机控制、离线恢复和浏览器存储行为。若网页版无法稳定满足长期离线收听，再评估独立 iOS 客户端。

这条路径预计需要少量按用量计费的临时存储和网络流量；只有用户主动“发送到手机”时才涉及上传。加密、链接失效和数据删除机制会先于对外开放完成。

## 数据与运行边界

- 桌面版的文章、项目、进度和生成结果默认保存在本机 `~/Library/Application Support/LawFlow/data/`；源码运行默认使用仓库下的 `data/`。导出目录可在应用中设置。
- 桌面应用的本地服务只监听 `127.0.0.1`。目前没有声息公共业务后端；未来规划中的临时手机中转不会改变现有默认行为。
- 使用外部文本模型或语音服务时，相关内容会发往用户选择的服务。调用前应确认材料有权发送；应用本地保存的密钥不等于第三方服务不会接收内容。
- 公开网页检索用于发现候选来源，用户确认导入后才会用于后续整理；抓取结果、AI 成稿和待核验提示都需要用户检查。
- 每日速听可订阅公开 RSS/Atom 来源并建立待审任务；目前需要桌面应用运行，不会自动发布最终音频。
