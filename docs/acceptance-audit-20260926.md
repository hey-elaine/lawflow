## 发布前必须完成

1. 取得 Apple Developer ID Application 证书并配置签名、公证凭据。用正式构建验证 `codesign`、`spctl`、`stapler`，再发布 GitHub Release。当前机器 `security find-identity -v -p codesigning` 返回 0 个有效身份，仓库 Actions secrets 为 0，Releases 为 0。
2. 在没有 Python、Homebrew、FFmpeg 和源码的干净 Mac 上，分别下载 Apple Silicon 与 Intel 的 DMG，安装、启动、重启、升级，并验证数据迁移与保留。目前只验证了本机 arm64 临时签名包。
3. 解决 MP3 生成依赖外部 FFmpeg 的问题。当前 DMG 未内置 `ffmpeg`、`ffprobe`；直接包含本机启用 GPL 的 Homebrew 版本之前，需要先确定分发许可方案。
4. 使用真实模型服务与合法的测试材料完成“导入长篇 DOCX → 确认大纲 → 生成 → 核验 → 审阅 → DOCX/MP3 导出”演示，记录耗时、成本及音频质量。本次仅验证了本地示例及模拟响应；不能把单元测试等同于真实模型效果。
5. 核对项目方案中要求的关键主张来源、审核记录、内容与音频版本关联，并补齐可供评委查看的成本与效果数据。现有导出包含审计摘要和来源映射，尚未完成逐项人工核验。
